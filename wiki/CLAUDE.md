# Wiki Conventions

How knowledge is organized in `wiki/`. Read before writing notes.

## Folder layout

| Path | Purpose |
|---|---|
| `wiki/index.md` | Top-level Map of Content. Only file at vault root. |
| `wiki/daily/` | Daily notes. Filename `YYYY-MM-DD.md`. Free-form. |
| `wiki/notes/` | Atomic notes. Kebab-case filenames. One idea per note. |
| `wiki/research/` | External references, papers, articles, quotes. |
| `wiki/people/` | Person profiles. Filename `firstname-lastname.md`. |
| `wiki/projects/` | Sub-project trackers (one file per active workstream). |
| `wiki/mocs/` | Maps of Content. Curated link hubs per domain. |

## Naming

- Filenames: lowercase kebab-case (`decision-adopt-boardgame-io.md`).
- H1 inside file: Title Case (`# Decision: Adopt boardgame.io`).
- Daily notes: `YYYY-MM-DD.md`.

## Linking

- Use Obsidian `[[wikilinks]]`, no `.md` extension.
- Link eagerly — broken links mark future notes worth writing.
- Folder-prefix only on name collision (`[[notes/foo]]` vs `[[research/foo]]`).
- Backlinks auto-generated by Obsidian — do not maintain manually.

## Tag taxonomy

YAML frontmatter, four orthogonal axes:

```yaml
---
tags:
  - domain/<area>        # 1+ required. What the note is about.
  - status/<state>       # exactly 1. adopted|deferred|superseded|verified|open|draft
  - scope/<milestone>    # 0-1. Milestone name if scoped.
  - origin/<reason>      # 0+. Why the note exists (incident, research, etc.).
---
```

## Governance

- Promote-don't-sprawl: new tag only if 3+ notes will use it.
- Exactly one `status/*` per note.
- MOCs, daily notes, and `index.md` stay untagged.

## Decisions

Significant decisions → `wiki/notes/decision-<slug>.md` atomic note. Include:

- Context
- Options considered
- Choice
- Why
- Date

Linked from `wiki/mocs/decisions.md` under the matching status section.

## Daily notes

Free-form. Capture as it happens. Lift long-lived items into `wiki/notes/` and reference back with a wikilink.

## Where to write what

| Content | Location |
|---|---|
| Cross-cutting feedback rules (apply across projects) | Claude memory (`~/.claude/memory/`) |
| Formal/public artefacts (PRD, specs) | `docs/` |
| Project state, decisions, daily logs, research | `wiki/` |

## On new note creation

1. Add wikilink from the relevant MOC.
2. If MOC missing, create it and add to `index.md`.
3. If today's daily note exists, append a one-line reference to the new note.
